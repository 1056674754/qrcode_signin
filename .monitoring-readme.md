## Design / privacy proof boundary

The client class is the exact approved ActivityV2 owned-client class. Its `_prepareEvent` deliberately avoids SDK9.47's global scope merge, and `_captureEvent` supplies its own isolation scope. Host/global processors, attachments and metadata cannot enter this client. Internal SDK processor failures have a bounded retry and original errors remain unmarked. No global `Sentry.init`, auto integrations, console/DOM/network instrumentation, replay, attachments, traces or profiling are enabled.

Only generated Sentry error-event identifiers, constant app/stage/endpoint tags, safe exception types, exact owned asset filenames, line/column coordinates, matching debug IDs, semantic route templates, release and environment survive the allowlist. Person data, auth/session material, OAuth queries, PKCE, QR values, business event identifiers, messages, bodies, headers, contexts and arbitrary scope metadata do not. Final transport rescrubs **every** event and reconstructs safe envelope headers, dropping every non-event item. Public source maps are forbidden.

React boundary wraps the app before first render. Owned global listeners are removable; the router observes only `pathname`. Explicit catches cover Login methods/redirect, OAuth/WeCom exchange, Events list/create/export, History read, Display event/check-in/proof/render, and Checkin submission/event/camera. Caught PocketBase errors are **not** passed to the SDK: only an owned constant-message error and static stage/endpoint/status are used. Expected HTTP4xx, cancellation and camera-denial errors stay quiet. Existing UI messages/retry paths remain intact, including expected OAuth400.

OAuth provider selection, callback URL, saved provider JSON, verifier/state keys, token save and pending-checkin return order are unchanged; current callback's existing state handling is not “fixed” in this monitoring task. QR proof/signature/monotonic-clock code is unchanged. The observation-only diff is additionally covered by the actual-dist offline protocol probe below.

7. Existing Compose frontend build args are now ineffective intentionally: configure public auth **before** the off-image build. Container orchestration instructions/support and an actual image build remain for parent review. Call the container configuration tool before any container CLI work.
